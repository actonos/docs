# Workspace & Semantic Memory

The **Workspace** provides a full-featured, sandboxed file management environment and integrated IDE combined with an automated **Semantic Memory (RAG)** indexing engine.

---

## 1. Integrated IDE & Viewers

ActonOS includes specialized viewers tailored for different file formats:

- **Code Editor (CodeMirror)**: Syntax highlighting, auto-indentation, line numbers, and error linting for 50+ programming languages.
- **Markdown Live Preview**: Split-pane or full-width rendering with GitHub-flavored tables, task lists, and LaTeX equations.
- **Interactive JSON Viewer**: Collapsible tree navigation with key search and type annotations.
- **Data Table Viewer**: Spreadsheet-like tabular viewer for `.csv` and `.tsv` files with sorting and filtering.
- **Media & Document Viewer**: Inline previewing of images (`.png`, `.jpg`, `.svg`), audio, video, and PDF documents.

---

## 2. File Operations & Batch Management

- **Upload & Download**: Upload single files or entire folders. Download individual items or export multi-file selections as a compressed `.zip` archive.
- **Context Menus**: Right-click any file to Rename, Duplicate (`_copy`), Move, or Delete.
- **Storage Statistics**: The Workspace stats bar displays total storage used, file counts, and storage breakdown by category (Code, Documents, Data, Media).

---

## 3. Your files keep their original names

When you upload `report.pdf` or ask the agent to save `weekly-notes.md`, those are the names you see on the Workspace page — and the same names the agent uses.

You can say things like:

- “Summarize `report.pdf` in the workspace.”
- “Save this as `weekly-notes.md`.”
- “Open the PDF I uploaded yesterday and extract the table.”

The agent looks up the file by name, then reads or processes it. You do not need internal IDs.

:::tip Workspace vs the agent’s scratchpad
**Workspace** is your folder. Files here appear in the UI and stay until you delete them.

The agent also has a **private scratchpad** for temporary scripts and unfinished work. Those files do **not** show up on the Workspace page unless the agent **publishes** them (for example: “save this PDF to my workspace”).
:::

### Opening PDFs and other documents in scripts

If you ask the agent to run Python (or another script) on an uploaded file, it uses the **original filename**. Typical flow:

1. You upload `report.pdf`, or the agent saves it to the workspace.
2. You ask: “Extract the first page of `report.pdf`.”
3. The agent finds the file, then opens it by that name.

This works for PDF, images, ZIP, Word, Excel, and similar files. The file is not converted to chat text first, so fonts and layout stay intact.

### Saving generated files back to Workspace

Ask the agent to write results **to the workspace** so you can open or download them:

- “Write a summary to `go_126_summary.md` in the workspace.”
- “Create `invoice.pdf` and save it to my workspace.”

For PDFs and other binary files, ActonOS copies the finished file as-is. Open **Workspace**, click the file, and download it.

You can also ask the agent to [send a workspace file to Telegram, Discord, Slack, WhatsApp, or Zalo](channels#sending-files-to-chat).

## 4. Automated Semantic Memory (Local Vector RAG)

Every text document, markdown file, or source code file placed in `/data/workspace/` is automatically processed into the **Hybrid Semantic Memory** index:

1. **Debounce Queue (1-Minute)**: Edits are enqueued in a durable SQLite debounce table to avoid thrashing during rapid file modifications.
2. **Chunking**: Text is split into semantic paragraphs with sliding window overlaps.
3. **Local ONNX Embeddings**: Chunks are vectorized using the local `multilingual-e5-small` model running in the loopback `embeddingd` daemon.
4. **Hybrid Retrieval**: Agents search workspace text through semantic memory (SQLite FTS5 + vector). The UI can also load chunks for a file via `GET /api/workspace/chunks?id=`.
5. **Manual Reindex**: Click the **Reindex Semantic Memory** button anytime to force a complete re-embedding of the workspace.
